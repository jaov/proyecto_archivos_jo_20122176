"How does a relational database implement SELECT author FROM books? In a 
relational database, every row in a table (e.g. the books table) is exactly 
the same length in bytes, and every fields is always at a fixed offset from 
the beginning of the row. So, for example, if each record in the books table 
is 100 bytes long, and the author field is at offset 23, then there are authors 
stored at byte 23, 123, 223, 323, etc. 

What is the code to move to the next record in the result of this query? Basically, it’s this:

pointer += 100;

One CPU instruction. Faaaaaaaaaast."
Joel Spolsky - https://www.joelonsoftware.com/2001/12/11/back-to-basics/

Para la capa de persistencia me inspire en Joel Spolsky, una de mis grandes influencias de programador.

Se va a guardar en archivos .dat con campos de tamano fijo, asi que no se va a usar std::string y se optara por arrays de char

Para metodos que solo hacen efectos secundarios retornar 0 es bien y retornar >0 se usa para errores

Se manejaran borrados suaves (soft deletes), para no mover el indice de los archivos binarios

Para los aleatorios queria usar PCG https://www.pcg-random.org porque es genial, pero decidi no incluir librerias externas.

Para asegurarme de unicidad queria depender solo del archivo, pero para eso tenia que hacer muchas llamadas como
`!dao.listarPorCampo(offsetof(Cliente, cedula.numero), c.cedula.numero).empty()` por cada campo que queria que fuera unico.
